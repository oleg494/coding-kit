# v3.2 design — Evidence-first eval loop

Date: 2026-08-24. Status: shipped (v3.2.0 + v3.3.0 telemetry/ablation, see docs/CHANGELOG.md; header updated 2026-09-04).
Supersedes: `docs/superpowers/plans/2026-08-24-eval-metrics-and-evolution.md` (deleted by this release).

## Problem — why the v3.1 candidate must not ship

The v3.1 branch (`HEAD 9a40537`, ahead of `origin/master` at v3.0.0) adds an eval
loop skeleton, but it is not releasable:

1. **CI execution risk.** `.github/workflows/evals.yml` runs a live executor as a
   subprocess that inherits the job environment and runs trap/trigger against the
   writable checkout; the matrix self-push (both legs `git commit && git push`) is
   racy and unsafe. Creds are not explicitly mapped today, but any future mapped
   model credential or token would be exposed to the agent. The inline "runs in temp
   dirs" comment overstates a guarantee only `task_runner` provides; the trap-suite
   runner runs at checkout cwd with inherited env.
2. **File-size gate loophole.** `scripts/file_size_baseline.json` grandfathers the
   714-line plan doc — a file *new in this release* — while the tool's own rule is
   "new files above hard always error; baseline is only for files already above hard".
   The changelog's "soft 0 hard 0" is true only through that loophole.
3. **No release/tag.** The v3.1 candidate is untagged and will be folded into 3.2.0;
   `origin/master` is still on v3.0.0.
4. **Too-thin schema.** `--json` payloads carry only `{name, verdict}` (or
   `{name, skill, verdict}`); no `run_id`, no duration, no per-attempt outcomes, no
   error capture — the exact shape the research doc said to fix *before* wiring.
5. **Model/executor conflation.** `model` is derived by slugging the executor CLI
   string, so two different CLIs wrapping one model read as two models.
6. **Mislabeled.** "quantitative benchmark" for 3 seed tasks — research L58 itself
   says 3 tasks is ~50× below statistical separation; it is a smoke canary only.
7. **Undiscoverable.** `README.md` and `scripts/kitctl.py` unchanged; no `tasks`/`trend`
   entry point.
8. **Debris.** The 714-line plan ships with 30/30 unchecked boxes; an untracked
   `eval/results/trap-dry-run-*.json` sits in the tree.
9. **Research corrections unapplied.** Decisions JSONL, enriched schema, rolling
   baselines, and CI sandboxing (research L56–61) are all absent.

## Goals

- A truthful, evidence-first eval loop: every verdict backed by a recorded attempt,
  duration, and error (when it failed); a trace tail where a producer has one.
- A versioned result schema (`schema v1`) with a unique `run_id`, atomic append,
  no overwrite, and a model label separated from the executor CLI.
- `--tries 2` task smoke with strong (deterministic) oracles — a canary, never a
  benchmark and never a gate.
- `trend` grouped by (kind, model) with a warn-only rolling baseline and
  failure evidence packets (name + error/trace + exact repro).
- Secure CI dry gates on Windows + Ubuntu; no self-push; no live shared-runner agent
  until real isolation + a secret proxy exist.
- Discoverability: `kitctl tasks` / `kitctl trend` + README eval row.
- Version cleanup: this release is **3.2.0**; there is **no separate v3.1 release**.

## Non-goals (explicit)

- No auto-evolution loop, no SkillOpt acceptance machinery, no meta-agent harness
  search (ADAS/SIA-style) in 3.2.
- No statistical or frozen pass-rate gate on task/trap/judged results — warn-only,
  always; deterministic checks remain the only always-block tier.
- No new third-party dependencies — stdlib only.
- No further memory-engine refactor beyond equivalence-tested extraction.
- No skill-edit proposals in 3.2: `trend` emits evidence packets only, never proposes
  or applies skill/AGENTS/OPS edits.

## Result schema v1

One JSON doc per run under `eval/results/`. `results_io.save_result` wraps the
producer payload; producers never set reserved keys.

Reserved metadata (loader-owned; producers may not overwrite):

| key | meaning | rule |
|---|---|---|
| `schema_version` | int `1` | loader default `0` for legacy docs |
| `run_id` | unique id, never reused | `<kind>-<utc-microseconds>-<uuid4>`; random uuid4 token — no collision for identical same-second runs |
| `kind` | `trap` \| `tasks` \| `trigger` | required |
| `model` | model label | explicit `--model` for live persistence; otherwise `unspecified` — never a slug of the full executor |
| `executor_name` | sanitized executable basename only | no args, no tokens, no full CLI string persisted |
| `utc` | ISO-8601 UTC | harness-authored |
| `harness_sha` | git rev of the harness | provenance |

Payload keys (producer-owned) remain at top level for backward compatibility:
`scenarios[]`, `rows[]`, `fired`, `passed`, `total`, `misses`, `attempts`, etc.
Loaders read reserved keys verbatim and pass everything else through untouched.

- **Atomic append / no overwrite (publication):** write the doc to a unique temp file
  in `eval/results/`, `flush` + `fsync` it, then publish by `os.link(temp, final)`
  (hard-link creation raises `FileExistsError` instead of replacing an existing
  target — atomic, never overwrites). On collision mint a fresh UUID/`run_id` and
  retry; `unlink` the temp after a successful link. Same-volume NTFS/ext4/APFS is
  the supported surface; if `os.link` is unavailable, fail loudly rather than weaken
  append-only. Loader tolerates orphan temp files by ignoring non-JSON temp suffixes.
- **Malformed-doc handling:** `load_runs` skips any file that fails to parse or
  lacks `run_id`/`kind`/`utc`, counts skipped docs, and reports `N malformed docs
  skipped` on stderr — never raises, never aborts the trend render. Legacy docs
  (no `run_id`) load with a synthesized id and `schema_version: 0`.

## Producers — truthful, per-attempt, backward-compatible

Every writer records per-attempt outcomes, durations, and errors; a PASS is only
recorded after the attempt that actually passed, a FAIL records *why*.

- **trap** (`eval/runner.py`): each scenario → `attempts[] = {verdict, duration_s,
  error?}` + final `verdict`; non-PASS carries `error` (timeout/judge mismatch) and
  a stderr/stdout trace tail where produced.
- **trigger** (`eval/trigger_eval.py`): each query → `{fired, duration_s, error?}`;
  misses collected as today.
- **tasks** (`eval/task_runner.py`): `--tries N` (default 2); per task `attempts[]`
  with `{verdict, duration_s, error_class?}` where `error_class ∈ {syntax_error,
  test_timeout, malformed_response, exhausted_context, user_asks, other}`; record
  `pass@1`/`pass@2` in the payload.

Backward compatibility: existing flags (`--executor`, `--json PATH|auto`,
`--timeout`, `--repeat`) keep working; new flags (`--model`, `--tries`) are additive.
Old-format docs keep loading with attribute defaults.

## Task smoke — strong oracles, never a benchmark

- Keep the 3 seed tasks; label output "task smoke", not "quantitative benchmark".
- `verify.py` oracles must be deterministic and self-contained: no wall-clock, no
  network, no unordered comparison of nondeterministic output, no flaky assertion.
  Exit `0`/`1` only.
- **Oracle strength:** a task passes only when its `verify.py` runs the sandbox's
  collected test suite and a regression test there fails against the pristine
  (pre-fix) fixture and passes after the fix — never a source-substring or test-count
  match as the pass condition. The current substring-based `verify.py` files are
  replaced with behavior-based oracles.
- `--tries 2` default; report pass@1/pass@2 as a *signal*, never a thresholded gate.
- No statistical gate: 3 tasks is far below the ~100–200 examples/route needed for
  separation.

## Trend — grouped, warn-only, evidence-first

- Table grouped by `(kind, model)`, newest run per group.
- Rolling baseline committed at `eval/baselines/{kind}.json`: last-N pass-rate per
  (kind, model). Newest run vs baseline → pass-rate delta (percentage points):
  **OK** `delta >= -3`, **WARN** `-8 < delta < -3`, **CRITICAL** `delta <= -8`.
  Warn-only: every band exits 0; deterministic checks stay the only blocking tier.
- Evidence packets only: per failure, emit failing scenario/task/query name, the
  recorded `error`/trace tail, and the exact re-verify command. v3.2 never proposes,
  suggests, or applies skill edits.

## CI — dry gates only until real isolation

- **Dry gates (always):** Windows + Ubuntu matrix — `pytest tests -q`, `runner.py`
  dry, `task_runner --dry-run`, `trigger_eval` dry, `check_file_sizes.py --ci`.
- **Artifacts, not self-push:** upload result docs via `actions/upload-artifact`;
  delete the `git commit && git push` step. CI never writes history.
- **No live agent on shared runners** until BOTH hold: (a) real isolation (container
  read-only repo mount + tmpfs writable surface, or a self-hosted equivalent), and
  (b) a secret proxy that holds model creds outside the agent's env. Until then live
  runs are local-only, with a subprocess env-whitelist that blocks `GITHUB_TOKEN`/secrets.

## Acceptance criteria

**TDD.** Each schema/producer/trend/kitctl change lands red-test-first, covered by
`tests/test_results_io.py`, `test_json_output.py`, `test_task_runner.py`,
`test_trend.py`, `test_kitctl.py`.

**Verification.** `python -m pytest tests -q` 100% green; `python scripts/kitctl.py
doctor` green; `check_file_sizes.py --ci` exits 0 with zero baseline entries for
files new in this release.

**Live-eval.** One real local live run recorded under the new schema: the full
18-scenario trap suite, all 3 task smokes at the default `--tries 2`, and the
80-query trigger corpus — at one explicitly recorded run/seed/model. Reported as
smoke, never as a benchmark. `python eval/trend.py` renders all three kinds and
emits no malformed-doc skips.

**Release.** `VERSION` and `profile.yml` = `3.2.0`; OPS header + changelog entry
citing the regression tests; SKILL_RUNTIME header `v3.2`; `git tag v3.2.0` at HEAD;
push to `origin/master`.

**Harness-sync.** Installed souls/skills re-synced to the kit's updated `AGENTS.md`
/`OPS.md` and skills for `~/.claude` (CLAUDE.md) and Hermes (SOUL.md + imported
skills); OPS eval section and README table mirror the new commands; `scripts/doctor.py`
stays green (including `check_reflex_commands`).

## Constraints

- Stdlib only; no `dspy`/`optuna`/`litellm`/`pydantic`/`jinja2`.
- Windows-safe: utf-8 reconfigure, no `shell=True`, `.cmd`/`.bat` via `cmd /c`,
  LF-safe writes; publication via `os.link` (see "Atomic append"), never `os.replace`.
- No auto-evolution / SkillOpt / meta-agent anywhere in this release.
